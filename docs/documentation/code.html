Running it

CommandWhat it does
python fetch_data.pyRuns the full pipeline at dev scope (IT, DE, EU27) and rewrites data/processed/.
python fetch_data.py --geo IT DE FR --refreshWider scope, ignoring the cache.
python fetch_data.py --no-writeDry run.
python build_site.pyRegenerates docs/data/*.json, then serves the site locally and opens a browser.
python build_site.py --no-buildServe only — what you want while editing HTML, CSS or JS.
python build_site.py --no-serveBuild only — what CI would run.

Serving matters: opening index.html from disk gives it a file:// origin, where fetch() is blocked and the page stalls on "Loading data…". The dev server also sends no-store, so a stale bundle can never be the reason something looks wrong.

The data pipeline

config.py

Declarative only — no I/O, no transformation. Holds the DatasetSpec registry of seventeen Eurostat tables, the geography scope, canonical size-class names, the two different "all sectors" NACE totals, and the verified uniqueness keys for each table.

extract.py — fetch and cache

Two behaviours worth knowing. The cache is keyed by request, so a cached file is reused only when it was fetched with the same query — changing --geo re-fetches rather than silently returning the previous scope. And Eurostat caps response size: an HTTP 413 makes the fetch split its geo list in half and retry recursively, rather than hard-coding a safe batch size per dataset.

parse.py — JSON-stat → tidy rows

Uses pyjstat to flatten each response to one row per observation, and extracts the category label vocabulary that later becomes the datamap. check_key_unique() asserts the declared key really is unique.

normalize.py — codes → canonical vocabulary

Every function fails loudly on codes it does not recognise. Eurostat adds and renames categories between waves, and a silent drop — or worse, a silent mis-join — would corrupt the headline numbers with no visible symptom. decode_ind_type() unpacks the individual-level dimension, which packs sex, age, education, labour status and citizenship into one code.

transform.py — assemble and join

Builds the enterprise-count universe (deriving bands like SMALL_10_49 by summing the finer bands Eurostat publishes — counts are additive, unlike percentages), then assembles the firm and individual tables and joins firm rows to the universe. join_report() reports the match rate per source, which is how a regression in the join gets noticed.

load.py and datamap.py

Parquet is the canonical artefact; the datamap is the companion dictionary that makes short codes readable — per column: label, role, dtype, nullability, distinct count; per value: the full code → label vocabulary; plus the caveats, carried inside the data product rather than living only in a spec file.

export.py — the data contract

Turns the canonical tables into the bundle the page fetches. Two rules are enforced here rather than left to the page:

  1. Every chart is pinned to exactly one unit.
  2. Unknown indicator codes raise, naming the code — a silently dropped series becomes an empty chart nobody notices.

Three further behaviours that are easy to miss:

  • enterprise_count is dropped wherever the unit is not a share of all enterprises, so the page cannot compute a weighted average on a base that would make it meaningless.
  • _rows() casts to object before nulling: on a float column pandas writes NaN back over None, and json.dumps would emit a bare NaN, which is not valid JSON. allow_nan=False makes that fail at build time rather than in someone's browser.
  • Charts the page never trends are trimmed to their last three survey years — history the browser would download and never look at.

Bundle shape

series.json   { chartId: { unit, base, weightable, indicators,
                           columns: [...], rows: [[...], ...] } }
labels.json   { geo, size_emp, nace_r2, ind_type, indicator, unit }
meta.json     { generated_utc, tables, sources, caveats }

Rows are positional arrays rather than objects — roughly half the bytes — and are rehydrated once, lazily, on the page. Current size: 13 charts, 43,721 rows, ~300 KB gzipped.

docs/app.js — the page

The central abstraction

Everything renders from a facet: a { geos, band } pair. band means a size class in the Companies view, a NACE section in Industry, and an age band in Individuals — the only difference is which column DIMENSIONS[view].field points at. That is why three views need one set of renderers, and why adding the Industry view required almost no new rendering code.

FunctionResponsibility
facets()The one or two slices a chart draws. Comparing by band holds countries fixed; comparing by country holds the band fixed.
aggregateValues()Combines countries — weighted by enterprise count where possible, plain mean otherwise, and reports which.
weightingMode()Decides weighting once for a whole series, so a trend line cannot mix methods across years.
absoluteCounts()Percentages → number of businesses, strictly same-year.
niceScale()Rounds the axis step, not the max — rounding the max alone still yields ticks at 18.75.
overlapWarning()Detects a band pair where one contains the other.

Chart primitives

rankedBars, groupedBars, lineChart, ordinalBars — plain inline SVG, no charting library. All four handle a null value by marking it "Not published" rather than omitting the row.

Section renderers and the view registry

headlineTiles, trendCard, rankingCard, comparisonCard, ordinalCard, breakdownRankCard, countsCard — each generic over the active dimension. VIEWS is a declarative registry: each section supplies an id, a narrative part, headings, and a render function, plus an optional available() predicate that removes the section when its data does not exist for the current selection.

State and URL

state = {
  view: "firm" | "sector" | "individual",
  geos: ["IT", ...],                      // one country, or several averaged
  firm | sector | individual: {
    band, compareMode: "band" | "geo", compareBand, compareGeos
  }
}

Mirrored to the query string on every change, so any state is a shareable link: ?view=sector&geo=IT,ES&band=C&by=geo&vs=DE,NL.

Adding things

To add…Do this
An indicator to an existing chart Append its code to the chart's indicators list in export.py and rebuild. An unknown code raises by name.
A new chart Add an entry to FIRM_CHARTS, SECTOR_CHARTS or INDIVIDUAL_CHARTS with a single unit, then add a section to the relevant VIEWS entry.
A new individual-level breakdown Add the raw ind_type code to INDIVIDUAL_CUTS with a kind and a short label.
A new dataset Add a DatasetSpec to config.DATASETS, then rerun fetch_data.py. Normalisation will raise on any unmapped category, which is the intended behaviour.

Deployment

GitHub Pages serves the docs/ folder from main — hence the folder name, since Pages offers only the repository root or /docs. There is no build step on the server, so docs/data/*.json must be committed. The consequence worth remembering:

Python changes need a rebuild and a commit of the JSON

Editing HTML, CSS or JS only needs a browser refresh. Changing the pipeline or a chart spec without rerunning build_site.py — or rerunning it without committing docs/data/ — leaves the published numbers out of step with the code that claims to produce them.
